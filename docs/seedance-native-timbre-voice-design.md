# Seedance Native Timbre Voice — Design

**Date:** 2026-06-29
**Status:** Approved design, pre-implementation
**Scope:** Replace the `seedance_native` lipsync engine (today: ElevenLabs-VO *content-follow*) with **native dialogue generation in a consistent, timbre-anchored voice**, polished Indian-English for English **and** Hindi.

---

## 1. Goal

When the user selects the Seedance-native audio mode, the spoken voice is **generated by Seedance itself** from dialogue in the prompt — not the pre-rendered ElevenLabs track. The character's voice must be:

- **Consistent** across every clip within one video.
- **Polished, neutral, urban Indian-English** — *not* an exaggerated/stereotypical accent — and the same identity must carry **Hindi** as well.
- **Faithful to the script** — the character must say *exactly* the scripted line: no improvised/off-script words, no repeats, no overlap across cut boundaries.
- Delivered in a **fast-paced, cut-to-cut** edit.

## 2. Verified premise (probe, 2026-06-29)

`scripts/probe_timbre_reference.py` confirmed on the live EvoLink `seedance-2.0-reference-to-video` model:

- Anchor audio said line X; prompt told the creator to say a **different** line Y with *"voice timbre references Audio 1."*
- Output transcribed (ElevenLabs Scribe) to **line Y** (overlap Y=0.81, X=0.00) — i.e. Seedance generated **fresh speech of the prompt's dialogue**, *not* a re-read of the anchor. **Not content-locked.**
- The user listened and confirmed the generated voice **matches the anchor's timbre** → the consistency mechanism works.
- Observed risk: the clip padded spare time with unscripted paralinguistics (`(sighs)`, `(birds chirping)`) → **script-fidelity must be enforced** (§7).

> **Blocker:** the EvoLink account is out of credits (51.34 / 108 needed per gen). The validation gate (§9) and any further live runs require a top-up.

## 3. Decisions (locked)

| # | Decision | Choice |
|---|---|---|
| D1 | Voice strategy | **Timbre-anchor hybrid** — one anchor clip, fresh native speech per clip referencing it |
| D2 | Consistency scope | **Within one video** (fresh anchor per run; no cross-run persistence) |
| D3 | Mode wiring | **Replace** the existing `seedance_native` engine (becomes timbre-anchor) |
| D4 | Fallback | If native QA fails / feature or credits unavailable → **auto-route to `syncso`** (ElevenLabs + sync.so) |
| D5 | ElevenLabs role | **Internal-only oracle** — measures line durations + donates the ~6s timbre anchor; **never muxed into output** |
| D6 | Voice persona | LLM-generated from the brief, constrained to polished Indian-English; multilingual (EN + HI) |
| D7 | B-roll voice | Per-beat **voice mode**; default = **background VO continues**; **silent** is the rare exception |

## 4. Architecture shift

Today the v2 pipeline is **VO-first**: the full ElevenLabs VO is both the *output voice* and the *master clock* (`pipeline.py:836–906` — VO duration drives re-planning, dead-air trim, and `beat_windows()`).

New mode keeps the VO as an **internal oracle only**:

```
brief
 └─ describe_character ─► character + VoicePersona (polished Indian-English, EN+HI)   [NEW]
 └─ plan_timeline ─────► beats, each tagged voice_mode ∈ {on_camera, background_vo, silent}  [NEW field]
 └─ ElevenLabs VO (INTERNAL ONLY)
        ├─ master clock  → beat_windows / per-clip requested durations  (unchanged machinery)
        └─ ~6s slice     → timbre anchor → uploaded ONCE → anchor_audio_url            [NEW]
 └─ per beat: Seedance r2v
        prompt: "<delivery per voice_mode> says exactly: '<dialogue_text>' …
                 voice timbre references Audio 1"   + persona descriptors             [NEW prompt]
        audio_url = anchor_audio_url   (SAME url for every speaking clip)             [NEW reuse]
        generate_audio = True,  model = NATIVE_LIPSYNC_MODEL
        └─ QA gate: transcribe clip → compare to dialogue_text → retry / fallback     [NEW guardrail]
 └─ assemble: per-clip native audio is the final mix (no global VO overlay)
```

Final audio = **100 % Seedance native**. ElevenLabs never reaches the viewer.

## 5. Voice-mode taxonomy (per beat)

Add `voice_mode` to `TimelineBeat` (`app/gemini.py:203`), set by `plan_timeline`:

| voice_mode | Meaning | Lip-sync | dialogue_text | Prompt delivery | Audio anchor |
|---|---|---|---|---|---|
| `on_camera` | creator speaks to lens (talking_head) | yes | required | "looks at the lens and says exactly: '…'" | yes |
| `background_vo` | line continues over a b-roll/product/action cutaway (**default for broll**) | no | required | "off-screen, the same creator's voice continues: '…' while she <action>" | yes |
| `silent` | pure action/holding product, **no dialogue** (rare exception) | no | empty | "<action>, ambient room tone only, no speech" | none |

- Mapping: `shot_type=talking_head` ⇒ `on_camera`. `shot_type=broll` ⇒ `background_vo` **by default**, `silent` only when the planner judges the shot carries no line.
- The existing contract "concatenating every beat's `dialogue_text` reconstructs `full_script`" still holds — `silent` beats contribute the empty string.

## 6. Components & file-level changes

1. **`VoicePersona` model + generation** — `app/gemini.py`
   - New structured descriptor: `gender`, `age_band`, `timbre`, `pace`, `warmth`, fixed `accent="polished neutral urban Indian English"`, `languages=["en","hi"]`, plus an explicit **negative** constraint (no exaggerated/sing-song/stereotypical accent).
   - Emitted by `describe_character` (alongside the existing `voice_vibe`) so "generate the character ref → also generate the voice" is one step.
   - Rendered to a compact prompt clause used in every speaking-beat prompt.

2. **Indian-English anchor voice** — `app/voice.py`
   - Constrain `voice_for()` / `VOICE_CATALOG` to a **polished Indian-English, multilingual** ElevenLabs voice (eleven_v3 handles Hindi in the same `voice_id`). The anchor is *how we control accent* — text-only accent steering is unreliable (research), the anchor pins it.

3. **Anchor lifecycle** — `app/pipeline.py`
   - After VO generation, cut a ~6–8s representative slice → upload **once** → `anchor_audio_url`. Reused for every `on_camera`/`background_vo` clip (no per-beat audio slicing — the current per-beat `slice_audio → pad → upload` for native is removed).

4. **Prompt builders** — `app/pipeline.py`
   - Rewrite `_native_talking_prompt` (`:494`): *"follow Audio 1"* → *"voice **timbre references** Audio 1"*, add persona clause, add strict-fidelity clause (§7).
   - Add `background_vo` and `silent` prompt variants (extend `_broll_motion_prompt` / dispatch by `voice_mode`).
   - Opus upgrade path (`write_motion_prompt`) must preserve the fidelity + timbre tokens (they are non-negotiable, not "baseline to beat").

5. **Clip request** — `app/pipeline.py:_clip_request`
   - `audio_url = anchor_audio_url` for speaking beats, `None` for `silent`. `generate_audio=True`. Duration ≈ the oracle's measured natural length for the line (tight → fast pace, less filler room).

6. **QA gate + fallback** — `app/pipeline.py` (+ small Scribe helper, `app/voice.py`)
   - Per clip: transcribe (Scribe) → normalized word-overlap vs `dialogue_text`. Pass if overlap **≥ 0.7** (tunable; ignores bracketed paralinguistics like `(sighs)`); else **1 retry** (tighter prompt + new seed); still failing ⇒ **fall back to `syncso` for that clip** (D4). Log every drift with the transcript.

7. **Assembly** — `app/assembly.py`
   - Native path already keeps per-clip audio and skips the global VO overlay. `silent` beats: ambient only. Confirm no ElevenLabs slice reaches the output.

8. **Config / UI** — `app/config.py`, `app/ui.py`
   - `seedance_native` label/help updated to "native voice (timbre-anchored, Indian-English)". No new engine id (D3).

## 7. Script-fidelity enforcement (the "no random/repeat/overlap words" requirement)

Three independent layers:

1. **Chunking** — each clip carries exactly one self-contained dialogue chunk, cut only on sentence boundaries (existing `split_long_windows` / sentence-boundary rule). No mid-sentence splits ⇒ no cross-clip word overlap or repeat.
2. **Tight duration** — request duration ≈ natural spoken length (oracle). Minimal spare time ⇒ Seedance has no gap to pad with improvised filler.
3. **Strict prompt + runtime QA** — prompt: *"says exactly: '<line>' and nothing else — no added, improvised, or repeated words; ambient/SFX only between phrases."* Then transcribe-and-verify each clip (overlap ≥ 0.7, 1 retry, then sync.so fallback per §6.6). This is the proven probe promoted to a guardrail.

## 8. Fast-paced cut-to-cut

- Keep ≤4.5s sub-beat splitting; prefer frequent cuts.
- Tight per-clip durations (no trailing dead air) keep momentum.
- `background_vo` lets the voice run continuously *across* visual cuts (talking-head → product cutaway) without an audio seam, so cutting fast doesn't chop the voice.

## 9. Validation gate (run first, once credits are topped up)

Before wiring into the live pipeline, extend the probe into a validation suite:

- **V1 Consistency:** 3 clips, same anchor, different lines → transcribe (fidelity) + listen/score timbre stability across all three.
- **V2 Accent:** confirm polished neutral Indian-English (not stereotypical) for an English line **and** a Hindi line, same anchor.
- **V3 Pure-text control (Test B, re-run):** does i2v native speech from a quoted line work without an anchor? (informs whether the anchor is strictly required.)
- **V4 Silent/background:** a `silent` beat stays speechless; a `background_vo` beat speaks off-screen over a product shot.

Green V1+V2 (and V4) gate implementation. Red → revisit D1/D4.

## 10. Risks & mitigations

| Risk | Mitigation |
|---|---|
| Native voice drifts off-script / repeats | §7 three-layer enforcement + QA gate + fallback |
| Timbre not stable across many clips | V1; if weak, shorten clips / standardize anchor; fallback per clip |
| Accent stereotyped or Hindi poor | Anchor pins accent (V2); fallback to ElevenLabs voice if needed |
| EvoLink credits / feature regress | D4 auto-fallback to `syncso`; mode is selectable, never the only path |
| Opus prompt upgrade strips timbre/fidelity tokens | Treat those tokens as mandatory, post-validate the upgraded prompt |

## 11. Out of scope

- Cross-run / persistent character voice library (D2 — within-one-video only).
- New video provider (fal.ai/Replicate) — only revisited if EvoLink validation fails.
- Beat-sync / music `@Audio1` features.
- Changes to the other engines (`syncso`, `heygen`) beyond serving as fallback.

## 12. Testing

- Unit: `VoicePersona` generation & clause rendering; `voice_mode` assignment mapping; prompt builders emit correct delivery + timbre + fidelity tokens per mode; anchor uploaded once and reused (same url); QA-gate pass/drift/fallback routing; `silent` beats request no `audio_url`.
- Integration (gated on credits): the §9 validation suite.
